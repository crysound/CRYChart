# CRYChart 性能自动化

`npm run build` 后执行 `npm run test:performance`。`npm run verify` 已包含这条命令。`npm run benchmark` 使用相同执行器，旧的 `gl.finish()` 计时方式已移除。

完整模式顺序执行下列五组测试。浏览器测量之间不并发运行，避免鼠标、CPU 和 GPU 负载互相干扰。

本库执行 CRYChart 独立负载。汇总中的 35 项应用业务测试仍由对应应用负责；设备采集、现场 IPC 和未合入的优化候选不被计为本轮已验证能力。

| 测试组 | 实际负载与检查 |
| --- | --- |
| `channels` | B64、B128：48 kHz、960 点/批、15 秒保留、双独立 F64 列、自动 X；各 3 轮，每轮 30 暖帧、128 测量帧；逐值核对保留数据 |
| `monitoring-short` | 九图共存；普通线性轴 1.5 px 和高精度轴 1 px，分别预填 28/60 秒；记录 Worker 接收、完整写入、Scope 提交、鼠标、帧间隔和长任务 |
| `monitoring-soak` | 上述两种轴配置分别真实运行至少 10 分钟；检查 1/5/10 分钟，记录全程分布、长任务和积压变化；停止时排空收到的批次 |
| `resources` | 128×48 kHz×60 秒：F64 再推进 12 数据秒，F32 共享布局再推进 120 数据秒；8 轮短历史内存循环及 6 轮分页生命周期 |
| `storage` | 显式开启原先默认跳过的两个 Node 分页性能用例；记录追加、填窗、暖追加、分配、复用和内存快照 |

`npm run test:performance:quick` 只检查短流程，不等于完整性能验收。快速模式和 `--groups` 子集运行的报告完整性为 `partial`，返回非零退出码，不能替代完整模式。

## 基准与限值

[基准清单](performance-baselines.json) 保存用户提供汇总中的 B64、B128 和 BScope 历史数据、协议、单位和来源摘要。历史对照数据只作静态参照，本轮不运行对照库，不宣称形成新的配对实验。

报告分别给出测试执行状态、协议完整性和性能限值验收状态。历史材料没有统一的 P95/P99、RSS 或持续吞吐合格阈值；没有配置限值时，性能限值验收为 `unconfigured`。这不会把测量结果改写成性能达标。

需要自动拦截约定的性能退化时，提供显式限值文件：

```json
{
  "B64.workMs.p95": { "max": 20, "unit": "ms" }
}
```

上面的 20 ms 只是配置格式示例，不是项目合格标准。运行方式：

```powershell
npm run test:performance -- --limits path/to/approved-limits.json
```

指标缺失、单位不一致或超过已配置限值均返回非零退出码。未知值保留为空，不填成零。三轮各自百分位的中位数与合并全部帧的分布分别保存，不混算。

## 测量范围

- GPU 完成等待使用真实同步单像素读回；可用的 GPU timer 区间单列。CPU、同步等待、GPU 区间和请求延迟可能重叠，不能相加当作端到端延迟。
- B64/B128 每批按绘制完成推进，20 ms 是数据时间跨度，不证明墙钟持续吞吐。容量测试加速推进数据时间，也不等于实时吞吐。
- Worker 仅发送进度元数据；不包含设备、实际波形传输或 Electron IPC 成本。
- 自有数值数组、JS heap、V8 backing、进程采样和 GL 申请量分别报告；不等同于完整显存驻留或整个进程长期稳定。显式 GC 等诊断仅提供观察结果，不替代必需测试。
- 对照协议的尺寸、DPR、样式、实验选项或统计口径不一致时，报告资格差异，不伪造同负载性能结论。

每次运行在 `codex_artifact/performance-current/<时间>/` 保存独立的 JSON、HTML、全帧数据和子任务日志，绑定当前构建和本轮会话。不会搜索历史目录继承通过数。
