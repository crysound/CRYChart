## 安装和运行

运行环境需要 Node.js 20 或更新版本。浏览器验证使用可见 Google Chrome。TypeScript 使用方的实测编译器是 5.9.3，类型声明也由此版本生成。本交付未承诺所有较旧编译器均兼容。TypeScript 5.9.3 的严格 NodeNext 和 Bundler 模式（`skipLibCheck: false`）最小消费检查均通过。原声明导入失败保留在 [类型与入口检查](../codex_artifact/delivery-validation/consumer-interactions/package-check/report.json) 中。

1. 进入源码目录。
2. 安装锁定依赖。
3. 构建代码和示例。
4. 启动本地服务器。

```powershell
cd D:\workspace\CRYChart
npm ci
npm run build
npm run dev
```

打开 <http://127.0.0.1:4178/>。服务器默认只监听本机。修改源代码后，需要再次运行 `npm run build`。

基础示例入口是 `/examples/index.html`。完整场景目录入口是 `/examples/official/index.html`。从选择器按编号或名称选择示例，使用页面中的暂停、重置、参数及主题控件。鼠标操作随图形类型变化，具体要求见 [逐例验收记录](functional-verification.json)。

示例数据随完整源码目录提供，包括钻石数据和已注明来源的脑部网格。保留 `examples/data` 的目录结构，避免数据请求失败。示例服务器只监听本机，实际测试使用可见 Google Chrome。

## 创建第一个图表

容器必须有明确高度。父元素高度为零时，百分比高度无法形成绘图区。

```html
<div id="chart" style="width:100%;height:400px"></div>
<script type="module">
  import { cryChart, ColorRGBA, SolidFill, SolidLine } from '/dist/crychart.js'
  const context = cryChart()
  const chart = context.ChartXY({ container: document.getElementById('chart') })
  chart.setTitle('温度变化')
  chart.getDefaultAxisX().setTitle('时间 / s')
  chart.getDefaultAxisY().setTitle('温度 / °C')
  const series = chart.addLineSeries().setName('传感器 1')
  series.setStrokeStyle(new SolidLine({
    thickness: 2,
    fillStyle: new SolidFill({ color: ColorRGBA(60, 210, 180) }),
  }))
  series.addArraysXY(
    new Float64Array([0, 1, 2, 3]),
    new Float32Array([22.1, 22.7, 23.0, 22.8]),
  )
  chart.fit()
  // 关闭页面或卸载组件时调用 context.dispose()。
</script>
```

图表通过 `ResizeObserver` 跟随容器尺寸。显隐切换后，可调用 `chart.resize()` 更新尺寸。当前接口也接受 `chart.resize(width, height)`。

## 数据追加、替换和保留

XY 系列接受对象点、XY 数组和列数据。

```ts
series.add([{ x: 0, y: 1 }, { x: 1, y: 3 }])
series.addArraysXY(new Float64Array([2, 3]), new Float32Array([2, 4]))
series.appendSamples({ x: [4, 5], y: [5, 3] })

// 整体替换数据。
series.clear()
series.addArraysXY(new Float64Array([10, 11]), new Float32Array([6, 7]))
```

同一批次的列长度必须一致。输入数组不会成为可改写的内部存储。`NaN` 和无穷值保留在浮点源列中。绘制层在这些位置断开折线。

自动 X 列只需要追加 Y：

```ts
const signal = chart.addLineSeries({
  schema: {
    x: { storage: Float64Array, auto: true, pattern: 'progressive' },
    y: { storage: Float32Array },
  },
})
signal.setMaxSampleCount(100_000)
signal.appendSamples({ y: new Float32Array([1, 2, 3]) }, { start: 0, step: 0.001 })
signal.appendSamples({ y: new Float32Array([4, 5]) }, { step: 0.001 })
// X 为 0、0.001、0.002、0.003、0.004。
```

后续批次不传 `start`，自动 X 会延续前一批。再次传入 `start` 会显式重设起点。`clear()` 清空数据并重置累计索引。

`setMaxSampleCount(100_000)` 设置精确保留上限。超过上限后只保留末尾样本。`setMaxSampleCount(undefined)` 取消上限。取消上限不会恢复已移除的数据。

存储窗口和可视窗口是两个状态。保留 10 万点后，可用轴区间显示其中一部分：

```ts
chart.getDefaultAxisX().setInterval({ start: 90, end: 100 })
```

8.2 参考库的 `DataSetXY` 同样支持数字形式的精确保留上限。部分旧版自动清理配置采用另一种策略。性能对比必须核验版本、实际保留数和累计索引，不能只比较配置中的上限数字。

## 共享数据集

多个系列可共享 `DataSetXY`。销毁系列不会销毁外部数据集。

```ts
import { DataSetXY } from 'crychart'

const data = new DataSetXY({
  schema: {
    time: { storage: Float64Array },
    value: { storage: Float32Array },
  },
})
data.setMaxSampleCount(100_000)
const line = chart.addLineSeries({ dataSet: data })
line.setDataMapping({ x: 'time', y: 'value' })
data.appendSamples({ time: [0, 1, 2], value: [3, 2, 4] })
const snapshot = data.readBack()
console.log(snapshot.data.time, snapshot.iSampleFirst)

// 卸载时先解除图表订阅，再释放调用方拥有的数据集。
context.dispose()
data.dispose()
```

`readBack()` 返回逻辑顺序的数组副本。`iSampleFirst` 是首个保留样本的累计索引。频繁读取完整副本会分配内存，不宜放在每帧绘制循环中。

## 可选分页存储

默认数据列使用 dense 存储。长历史可以显式选择分页候选：

```ts
const data = new DataSetXY({
  columnStorage: { mode: 'paged', pageSize: 1024 },
  includesNaN: true,
  schema: {
    x: { storage: Float64Array, auto: true, pattern: 'progressive' },
    rawY: { storage: Float64Array },
    renderY: { storage: Float64Array },
  },
})
data.setMaxSampleCount(48_000 * 60)
const samples = new Float64Array([0.2, 0.4, 0.1])
data.appendSamples({ rawY: samples, renderY: samples }, { start: 0, step: 1000 / 48_000 })
console.log(data.getStorageStats())
```

同存储类型、逐值相同的内部页可以共享；需要修改时按页分离。两列内容不同会增加占用，不能假定始终减半。自动 X 保持原批次的 Float64 计算表达，不分配完整 X 数组。

`getStorageStats()` 可查看自有数值字节、唯一页、页池及逻辑容量。完整 `readBack()` 仍会创建副本，不应每帧调用。销毁图表后，调用方仍需销毁自己持有的数据集。

冻结构建 `f8e8bcd1…` 已在可见 Chrome 中通过 128 通道、48 kHz、60 秒保留及 12 秒回绕的数据检查。测试耗时包含生成和逐值核验，不能作为实时吞吐结果。绘制质量、持续性能和长期稳定性仍待通过。详见 [性能说明](性能说明.md)。

## 坐标轴和交互

```ts
import { AutoCursorModes } from 'crychart'
chart.getDefaultAxisX().setInterval({ start: 0, end: 10 })
chart.getDefaultAxisY().setInterval({ start: -2, end: 2 })
chart.setAutoCursorMode(AutoCursorModes.disabled)
chart.setMouseInteractionsEnabled(false)
```

自动游标和鼠标缩放是独立开关。只关闭鼠标缩放不会关闭游标。

当前 XY 默认操作包括滚轮缩放、左键框选缩放、右键拖动平移和双击适配。多轴、极坐标和专用图表具有各自的操作规则。参考示例的全部默认操作仍需逐项核对。

固定区间适合应用管理视窗。需要重新显示全部数据时调用 `chart.fit()`。另一个 Y 轴使用 `chart.addAxisY()` 创建。系列通过 `axisY` 选项绑定新轴。

分区波形在同一图表中创建多个 Y 轴：

```ts
chart.getDefaultAxisY().dispose()
const axisY = chart.addAxisY({ iStack: 0 })
const secondAxisY = chart.addAxisY({ iStack: -1 })
chart.addLineSeries({ axisY })
chart.addLineSeries({ axisY: secondAxisY })
```

相同分组内，负方向的栈索引依次位于下方。分区系列共享图表的绘制上下文，并各自裁剪到绑定轴区域。显式分页候选已通过 128 通道、48 kHz、60 秒保留容量检查；实时性能、完整画质和长期稳定性仍未通过。该结果仅适用于记录中的候选配置。

## 新增接口与验证边界

本节记录最近的实现。对应的 Node 检查和可见 Chrome 检查需要分别核对 [验收记录](acceptance.json)，不能用较早交付的通过数量替代。

图表提供原生图例 `chart.legend`。它可以自动注册新系列，也可以手动添加条目：

```ts
chart.legend.setOptions({ visible: true, addEntriesAutomatically: true })
const line = chart.addLineSeries().setName('通道 1')
chart.legend.setEntryOptions(line, { text: '入口温度' })
chart.legend.remove(line)
```

添加 LUT 色标时，`getEntries()` 返回的 `entry.component` 是移除句柄。需要调用 `chart.legend.remove(entry.component)`；不要把该句柄假设成原来的 LUT 对象。`clear()` 只清理图例条目，数据系列有自己的生命周期。

如果示例或应用已绘制自定义DOM图例，请调用 `chart.legend.setOptions({ visible: false })` 关闭原生图例，避免同一图表显示两份图例。

XY 与热图支持 `setCursorMode`、`setCustomCursor`、`solveNearest` 和格式化回调。`solveNearest({clientX, clientY})` 使用浏览器客户区坐标。结果中的坐标标记和结果表位置带有各自坐标系，不能直接当作屏幕像素。

```ts
chart.setCursorMode('show-nearest')
chart.setCustomCursor(({ hit, hits, mouseLocation }) => {
  // 由应用更新自己的结果面板；hit 可能为空。
  console.log(hit, hits, mouseLocation)
})
// 恢复内建游标绘制。
chart.setCustomCursor(undefined)
```

应用自行监听鼠标并绘制光标时，显式关闭原生自动光标：

```ts
chart.setCursorMode(undefined)
chart.getCursor().setVisible(false)
```

仅调用 `setVisible(false)` 不能作为跨库关闭自动光标的约定。参考库可能在下一次悬停时重新显示它。内建格式化回调的调用次数也不保证跨库一致。

固定 XY 热图尚未写入的单元初始为 `0`。`clear()` 保留网格尺寸并将单元归零。显式写入的 `NaN` 仍保留为 `NaN`。极坐标热图的初始值和清空值保持 `NaN`。

`heatmap.solveNearest()` 的公开查询会定位到现存边缘单元。滚动方向尚未写入的未来位置返回空。图表原生 `show-pointed` 光标仍按图形的实际覆盖范围命中，不因公开查询的边缘定位而扩大范围。

固定 XY 网格使用负步长时，公开 `getXMin/getXMax` 和 `getYMin/getYMax` 返回排序后的数值界限。内部纹理坐标、滚动端点和极坐标继承接口保留原有方向。滚动热图的有限清理数量与参考库仍有差异，不能只根据相同配置推定保留数据相同。

`heatmap.getFillStyle()` 返回当前填充对象。固定和滚动 XY 热图的 `getWireframeStyle()` 返回网格线样式；`setWireframeStyle(style)` 接受样式对象，也接受基于当前样式的回调。默认样式来自主题，需要只显示色块时可显式使用 `setWireframeStyle(emptyLine)`。普通 GPU 和 Canvas 绘制路径均应用此样式；`highPrecision` 路径仍不绘制网格线。

饼图、漏斗图和金字塔图的 `setLabelFormatter` 第二个参数是 0–1 的 `relativeValue`。显示百分比时需要乘以 100，例如 `(_, relativeValue) => (relativeValue * 100).toFixed(2) + '%'`。回调次数及切片枚举顺序不作为跨库兼容保证。

柱图默认在指针悬停时提亮目标柱，移开后恢复原色。点击保留 `getSelectedItem()`、`select` 事件及选中状态切换。点击后的其他柱保持原有亮度。透明颜色保持透明，原始数据和颜色对象保持不变。

自定义 `Cursor.setPosition(...positions)` 可以一次设置多个标记。每个位置分别指定 `pointMarkerScale` 和 `resultTableScale`；直方图标记的位置和结果表锚点可以使用不同坐标系。空参数调用会清空位置。

极坐标系列的 `setData([{angle, amplitude}, ...])` 在原数据集上原子替换数据。共享该数据集的消费者仍保留同一个数据集对象。`getData()` 返回角度与幅度，`translateCoordinate` 负责坐标转换；`setCursorFormattingOverride` 用于定制结果行。

轴提供 `setTitlePosition`、`setMarginAfterTicks`、`setMargins` 和刻度样式配置。标题位置接受 `start`、`center`、`end`、`center-chart`。这些设置参与布局或绘制，具体行为以当前构建的可见测试为准。

`axis.getTickStrategy()` 返回 `Empty`、`Numeric`、`DateTime` 或 `Time` 类型名。通过 `setTickStrategy(type, ticks => ...)` 的第二个参数配置样式；不要把读取到的类型名当作样式对象使用。

空间足够时，`axis.setLength({pixels: 620})` 会给轴分配 620 个 CSS 像素。坐标转换和实际绘制都使用该长度。全部采用固定长度的堆叠轴会保留剩余空白，末轴不会自动拉伸。相对长度轴仍分配可用余量。超出可用空间的配置另有观察记录，尚未完成全部参考边界验证。

### 数值刻度的小数位数与有效数字

通过 CRYChart 格式化接口配置显示精度。`toFixed(3)` 表示固定 3 位小数；`toPrecision(6)` 表示 6 位有效数字；`toExponential(3)` 表示科学计数法的小数部分保留 3 位。这些函数只生成显示文本，不修改数据集中的数值。

```ts
import { AxisTickStrategies } from 'crychart'

const axisY = chart.getDefaultAxisY()
axisY.setTickStrategy(AxisTickStrategies.Numeric, ticks =>
  ticks.setFormattingFunction(value => value.toFixed(3))
)
// 同一个接口也可配置有效数字。
axisY.setTickStrategy(AxisTickStrategies.Numeric, ticks =>
  ticks.setFormattingFunction(value => value.toPrecision(6))
)
```

`setFormattingFunction` 统一配置主刻度、次刻度、极端刻度的格式器和光标。随后可以分别覆盖。格式器不负责启用相应刻度层；例如次刻度标签仍需配置可见的标签填充样式。

```ts
axisY.setTickStrategy(AxisTickStrategies.Numeric, ticks => ticks
  .setMajorFormattingFunction(value => value.toFixed(2))
  .setMinorFormattingFunction(value => value.toFixed(4))
  .setCursorFormatter(value => value.toFixed(6))
)
```

`axisY.formatValue(value)` 使用光标格式器。`setCursorFormatter(undefined)` 恢复光标默认格式，不改变主、次刻度的配置。再次统一设置 `setFormattingFunction` 会覆盖之前的分层配置；单纯再次选择 `AxisTickStrategies.Numeric` 不等于清空已有配置。

`setFormattingOffset(offset)` 在格式化前给显示值加偏移，不移动数据点；传入 `undefined` 清除偏移。数据存储精度与显示小数位数是不同事项。增加显示位数不能恢复已丢失的输入精度。

历史可见 Chrome 检查覆盖固定小数、有效数字、科学计数法、分层覆盖与实际光标。需要关闭轴滚动边距时，显式调用 `setScrollMargins(false)`。显示格式、缩放回调范围、长标签布局和自动网格需要按当前图表配置验收，接口检查不代替完整场景运行。

主线支持 `setCurvePreprocessing({type:'spline', resolution:0})`。零分辨率不添加插值点，保留原始折线几何。其他尚未实现的预处理配置会返回错误，不会静默忽略。需要样条时，可使用专用样条系列，并核对其支持范围。

## 消费者滚动、视窗限制与高亮

`axis.setAnimationScroll(true)` 启用自动滚动动画。`false` 或 `undefined` 使用立即滚动行为。动画只跟随自动更新的区间；显式 `setInterval` 和 `fit(false)` 立即定位。停止、隐藏、清空和销毁会取消待处理动画。

当前实现已在可见 Chrome 中验证真实中间帧和最终位置。缓动曲线与动画时长不承诺和参考相同。原始样本不会因动画改写。[本轮滚动对照](../codex_artifact/functional-completion-20261104/axis/official-xy-advanced/2026-11-04T04-14-39-657Z/report.json)。

`getIntervalRestrictions()` 初始返回 `undefined`；配置对象按原引用返回。回调形式在读取时获得当前区间与数据边界，并返回解析结果。显式调用 `setIntervalRestrictions(undefined)` 后，getter 返回 `undefined`。回调限制的自动执行未实现。

仅XY线性轴的正数、有限常量 `intervalMax` 已执行约束。设置限制本身不改变当前区间；后续手动提交围绕请求中点限宽。真实滚轮先限制缩放比例，保留事件锚点；连续超限保持已达上限的区间。

```ts
const axisX = chart.getDefaultAxisX()
axisX.setAnimationScroll(false)
axisX.setIntervalRestrictions({ intervalMax: 5000 })
axisX.setInterval({ start: -1000, end: 7000, stopAxisAfter: true })
// 实际区间为 500..5500。
axisX.setIntervalRestrictions(undefined)
```

`intervalMin`、各端点限制、对数轴、Polar和3D限制未在本次扩展。getter可读这些配置不代表相应约束已生效。

Polar与已覆盖的XY、3D、几何系列支持 `series.setHighlight(true)` 和 `setHighlight(false)`；数值强度限制在0到1。`setAnimationHighlight(false)` 使用静态高亮，`true` 使用原创脉冲。高亮不改写原始值或用户样式，关闭后恢复原色。脉冲时长、相位不承诺与参考一致。

`chart.setAnimationsEnabled(false)` 会更新已有系列，并影响随后创建的系列；重新启用恢复相应动画。world3D的滚轮动画仍同时受此开关控制。隐藏、清空与销毁的调度已做有界回归，不代表所有系列和参数均完整兼容。

## React 最小生命周期

在已安装 React 的应用中使用以下组件。图表在挂载后创建，在卸载时释放。

```tsx
import { useEffect, useRef } from 'react'
import { cryChart } from 'crychart'

export function SignalChart() {
  const host = useRef<HTMLDivElement>(null)
  useEffect(() => {
    if (!host.current) return
    const context = cryChart()
    const chart = context.ChartXY({ container: host.current })
    chart.addLineSeries().add([{ x: 0, y: 1 }, { x: 1, y: 2 }])
    chart.fit()
    return () => context.dispose()
  }, [])
  return <div ref={host} style={{ width: '100%', height: 400 }} />
}
```

实时数据订阅也应在清理函数中解除。开发环境重复挂载时，每次创建都必须对应一次清理。

## 显式波形优化选项

从生产构建 591a 起已包含以下四个选项，当前 904de1b 保留。默认均不启用；省略它们会保留常规路径。

| 选项 | 本轮使用值 | 作用 |
| --- | --- | --- |
| `experimentalLineDisplayPixels` | `1` | 按最多 1 个物理像素的横向跨度选择显示点，原始数据完整保留 |
| `experimentalLineCoverage` | `true` | 用线段覆盖率并集绘制，避免同一折线重叠处重复合成透明度 |
| `experimentalOwnedCoverageFrame` | `true` | 满足条件的私有默认目标帧使用已知 GL 状态；混合路径仍保存和恢复状态 |
| `experimentalGpuClipPolicy` | `'contained'` | WebGL2 数据图层仅绘制分区内完整物理像素；Canvas、3D 和 UI 不受此项影响 |

以下示例采用不透明 2px 普通实线、递增均匀自动 X 和有限 dense Y：

```ts
import { cryChart, ColorRGBA, SolidFill, SolidLine } from 'crychart'

const context = cryChart()
const chart = context.ChartXY({
  container: document.getElementById('chart')!,
  experimentalLineDisplayPixels: 1,
  experimentalLineCoverage: true,
  experimentalOwnedCoverageFrame: true,
  experimentalGpuClipPolicy: 'contained',
})
const line = chart.addLineSeries({
  includesNaN: true,
  schema: {
    x: { storage: Float64Array, auto: true, pattern: 'progressive' },
    y: { storage: Float64Array, pattern: null },
  },
})
line.setMaxSampleCount(720_000)
line.setStrokeStyle(new SolidLine({
  thickness: 2,
  fillStyle: new SolidFill({ color: ColorRGBA(60, 210, 180, 255) }),
}))
line.setCurvePreprocessing({ type: 'spline', resolution: 0 })
const values = Float64Array.from({ length: 48_000 }, (_, i) => Math.sin(i * 0.01))
line.appendSamples({ y: values }, { start: 0, step: 1000 / 48_000 })
chart.getDefaultAxisX().setInterval({ start: 0, end: 1000 })
chart.getDefaultAxisY().setInterval({ start: -1.25, end: 1.25 })
// 后续追加沿用 step；组件卸载时调用 context.dispose()。
```

这是单通道接口示例，不是完整性能夹具。该夹具使用 64 通道、两列独立 F64 Y、15 秒保留和显示。显示跨度允许大于 0 且不超过 4，但本轮性能结论只绑定值 1。

双极值显示策略要求线宽恰为 2，颜色完全不透明，轴线性且未反转。X 必须是严格递增、均匀的自动列。Y 必须使用 dense 存储，且整个保留窗口内的值均有限。库检查真实数据，不只依赖 schema 提示。

NaN/Inf、非均匀 X、样条、虚线、点标记、LUT 或不满足条件的路径使用既有回退。断线和原始读回仍保留。低于 4096 点时不会进入该显示缓存路径。

`experimentalOwnedCoverageFrame` 仅在整帧满足私有默认目标、清屏和纯覆盖率折线条件时启用。混合点、热图、虚线、自定义 FBO 或非清屏帧保留状态保护；调用方不能将它理解为通用免恢复选项。

`series.getLineDisplayStats()` 记录保留量、显示提交量及派生缓存容量。隐藏时释放派生数组和位置 buffer，只保留恢复所需的数值原点及失效元数据。换源、清空、绑定或投影变化仍重新验证；销毁释放全部派生状态。外部共享 DataSet 由调用方管理。

上述开关已进入源码，但仍默认关闭。启用后需要检查原始值、极值、NaN 缺口、游标和窗口回绕。单项检查不代替画质、P95 延迟、内存或 128 通道验收。负载和计时范围见 [性能说明](性能说明.md)。

常规示例提供 [OpenTest 波形预设](../examples/channel-lab/index.html?preset=opentest)。不带查询参数仍为普通模式。预设启用上述四项和 2px 不透明线，并提供隐藏、恢复和清空操作。功能证据绑定 fd1c 来源的独立 lab e649，未在后续功能构建重跑。检查范围为 16、64、128 通道，每通道 1 秒历史。

首轮 11/12，定向补测 1/1；128 合成图另有固定视口补证。原空白 fullPage 截图保留为无效采集，不作为通过证据。这不是 128×15 秒或 60 秒容量，也不是新的性能认证。见 [预设功能复核](../codex_artifact/channel-lab/opentest-preset-2026-11-03/review.json)、[128 呈现记录](../codex_artifact/channel-lab/opentest-preset-2026-11-03/presentation-2026-11-03T06-04-49-466Z/report.json)、[固定视口画面](../codex_artifact/channel-lab/opentest-preset-2026-11-03/presentation-2026-11-03T06-04-49-466Z/fit-viewport.png)。

## 折线覆盖率与实验选项

当前默认的递增 X 实线使用覆盖率并集合成。它修复尖锐折点的缺口，并避免同一条半透明折线在交点重复加深。原数据、修订缓存和增量上传保持。

实验性渲染配置仍可单独选择：

```ts
const chart = cryChart().ChartXY({
  container: document.getElementById('chart'),
  experimentalLineCoverage: true,
  experimentalLineDisplayPixels: 1,
})
```

两个显式选项默认均不启用。`experimentalLineCoverage` 选择实验性专用覆盖率管线。`experimentalLineDisplayPixels` 控制显示点选择。默认缓存管线也已复用覆盖率合成。同一条线的线段先合并覆盖率，再合成一次颜色。

当前修复新增 R8 遮罩和合成步骤。在已测百万点场景中，缩放仍保持上传次数 1→1，上传字节不变。绘制调用由 1 次变为 2 次，顶点提交量约翻倍。原小视口场景的遮罩容量为 524,288 字节。以上是指定场景的资源记录，当前构建尚未完成新的正式性能测量。

用于历史探测的显式方向及偏移缓存配置仍保留原结果，未计入本次默认路径修复。原输入、失败记录与完整范围见[当前修复证据索引](../codex_artifact/reference-expansion-20261104/next-batch-reference-replay-20261105/categorical-and-fixes/cohorts/current-0922-remainder-02/current-evidence-index.json)。

构建 `3a0d2147…` 的混合折线、点、虚线、分区裁剪、自定义绘制目标及异常恢复共 13 项可见检查通过。128 通道短配对仍为 29.6 ms 对参考 18.6 ms，不能视为性能目标完成。完整历史容量通过的是另一个显式分页夹具，也不能替代该候选的实时性能与画质验收。

## 富文本提示框和格式化顺序

结果表支持逐单元格文字、字体、填充色和组件色标。测量和绘制共用一份布局，避免更换字体后文字越出已测边界。下面展示已有 cursor 的表格设置：

```ts
cursor.setResultTable(table => table.setContent([
  [{ text: "通道" }, { text: "当前值" }],
  [{ component: line }, {
    text: "300 Pa",
    font: new FontSettings({ family: "Arial", size: 16, weight: "bold" }),
  }],
]))
```

从 `crychart` 导入 `FontSettings`。`cursor` 和 `line` 分别是调用方已有的游标与系列。显式数值文字由调用方更新；需要自动数据读数时，使用图表的默认格式化或对应 formatter。

默认 XY show-all 的表格布局取决于数据配置。命中的系列共用 X 轴，且各自 X 列均声明递增或递减时，表格使用公共 X 表头。其他情况分别显示每个系列的 X/Y。每个系列使用所属 Y 轴的单位。原生 show-all 的二维最近点查询不保证所有命中点的 X 相同；共享 X 读取需要调用方的相应交互逻辑。

默认图表格式化对每个系列调用一次系列 formatter。设置显式 chart formatter 后，chart formatter 管理整张表；库不会再追加执行系列 formatter。

历史对应构建完成 XY、Polar、Histogram 和 TDF 的两主题专项，结果不自动计入后续构建。超宽表格仍可能被画布裁剪，库没有自动折行。Polar 的 marker、整体半径、圆角间距与完整样式组合需要按使用场景验收。性能与内存实验的开关和限制见 [性能说明](性能说明.md)。


## 字体、端点标签与三维坐标

当前构建中，刻度字体回调会先接收主题字体。只调用 `font.setSize(12)` 会保留字体族、字重和样式；显式完整字体设置仍优先。

二维坐标轴按实际字形宽度和高度避让标签。主刻度标签优先，次刻度标签按剩余空间显示。网格线和刻度线保留。格式化后的文字保持原样，不会自动降低小数精度。单个标签大于整条轴的可用空间时，该标签暂不绘制；可以加宽容器、减小字号或显式调整格式。

本轮可见 Chrome 检查覆盖 360/600/1050 像素宽度、13 位时间戳、0/3 位小数和真实滚轮。完整数据不因避让改变。DateTime 按实际标签尺寸选择日历刻度，包括周和月。5 项已测场景尚未覆盖全部日期范围。[标签避让记录](../codex_artifact/reference-functional/axis-label-collision/2026-11-04T04-21-01-791Z/report.json)、[日历刻度记录](../codex_artifact/reference-functional/datetime-calendar-paired/2026-11-04T04-19-08-770Z/report.json)。

完整 XYZ 点可以转换到当前三维图的浏览器位置：

```ts
const client = chart3d.translateCoordinate(
  { x: 1, y: 2, z: 3 },
  chart3d.coordsAxis,
  chart3d.coordsClient,
)
const minimumZ = line3d.getZMin()
const maximumZ = line3d.getZMax()
```

`chart3d` 和 `line3d` 是已有的三维图表与系列。`client` 返回 `clientX`、`clientY`。空数据的 Z 极值为 `undefined`，极值按有限数值计算。此修复使用当前投影，不会改变图像或默认相机。无 Z 的既有 XY 调用保留。

从 fd1c 起默认使用 world/XYZ 相机、透视投影和自动适配。`setProjection('orthographic')` 可切换正交投影；`setCameraAutomaticFittingEnabled(false)` 可关闭自动适配。`setCameraLocation({x, y, z})` 使用世界坐标相机，`getCameraLocation()` 返回当前模型的位置。

da4855 修正了 world3D 的 `fit()` 默认多余5%留白；显式留白设置、XY、Polar和legacy3D行为保持。默认相机与固定XYZ场景的来源坐标最大误差分别从24.225降至4.658 px、从13.868降至0.7143 px。剩余默认相机和画质差异仍存在，不表示与参考完全等价。[构建与回归](../codex_artifact/delivery-validation/world-fit/functional-validation-2026-11-03T06-15-03-274Z/report.json)。

完整 XYZ 可在轴坐标与 `chart3d.coordsWorld` 间转换，也可投影到 client/pixel。屏幕反投影和 relative XYZ 没有明确平面/深度合同，仍会抛出异常。显式 `setCameraLocation({azimuth, elevation, zoom})` 保留旧角度模型；可用 `experimental3DCameraModel:'legacy'` 显式创建旧模型。两个模型不能把相机对象形状混用。

world 模型默认启用滚轮缩放动画。`setAnimationZoom(false)` 关闭渐进动画，输入仍通过动画帧调度处理。`setAnimationsEnabled(false)` 也关闭该动画。短时间连续输入使用有界状态，隐藏与销毁清理待处理输入。相机、光照及布局需要分别检查，功能修复不自动产生新的性能成绩。

## 消费接口的显示选项与时间游标

OpenTest 兼容接口的 `fontSize` 会应用到图表标题、轴标题和数字主刻度。`showYCursor: false` 同时关闭 Y 游标标记及网格线。已有数据、缩放方式和生命周期接口保持。当前只完成独立验证，尚未在 OpenTest 应用内替换。

时间轴把输入解释为毫秒，默认格式随当前范围选择秒、毫秒、微秒或纳秒显示。45 ms 在毫秒档显示为 `00:00:00.045`，在微秒档显示为 `00:00:00.045000`。负号保留，小时可超过 24。默认格式会加入 `timeOrigin`；将起点设为 `undefined` 可清除起点。显式格式器收到应用 `formattingOffset` 后的值，不自动加入 `timeOrigin`；未配置偏移时收到原值。

也可以明确指定时间显示精度，使它不随缩放变化：

```ts
import { AxisTickStrategies, TimeFormattingFunctions } from 'crychart'

chart.getDefaultAxisX().setTickStrategy(AxisTickStrategies.Time, ticks => ticks
  .setMajorFormattingFunction(TimeFormattingFunctions.hhmmssmmm)
  .setCursorFormatter(TimeFormattingFunctions.hhmmssmmmuuu)
)
```

4 个公开预设分别是 `hhmmss`、`hhmmssmmm`、`hhmmssmmmuuu`、`hhmmssmmmuuunnn`。秒和毫秒档截去更小单位，微秒和纳秒档对末位舍入。CRYChart 会正确传播舍入进位，参考库在部分边界输入下丢失进位的差异单独记录。主刻度格式器只控制相应标签。光标使用自己的配置。`setCursorFormatter(undefined)` 恢复默认时间格式，不回退到主刻度格式器。

当前 `Time` 自动主刻度使用以下间隔。跨度区间均包含左端点，不包含右端点。

| 轴跨度 | 主刻度间隔 |
| --- | --- |
| 15–90 秒 | 15 秒 |
| 90 秒–10 分钟 | 1 分钟 |
| 10 分钟–1 小时 | 15 分钟 |

自动次刻度结合实际标签宽度避让，范围限于 15 秒至不足 1 小时。后续主题字体可作用于未显式覆盖的默认样式。显式字体、填充及自定义刻度配置保持优先。默认容器宽度、小时范围与部分舍入边界仍有参考差异，不能据此认为所有网格已一致。

TDF 的有限强度色标取自当前 LUT。默认强度显示 1 位小数。实际消费的自定义覆盖仍可减 40 并显示 3 位小数，单位放在行标题中。无效值不会显示误导性的有限值色标。NaN、未写入列和清理时机与参考仍有差异。
