# CRYChart 性能说明

性能结论绑定实际构建和测试配置。历史结果不能转记为后续源码的成绩。接口名称清理后的结果，以重新运行的测试记录为准。

## 高精度历史波形与 Scope

2026-11-09 的受控测试比较 CRYChart 自身的两个构建。历史图使用 `linear-highPrecision` X 轴。每图 2 条主序列，每条保留 2,880,000 个样本。每个历史图保留 5,760,000 个原始样本。测试没有删除原始数据来减少绘制负担。

测试在真实可见 Chrome 156 中运行，图形后端为 ANGLE AMD Direct3D11。设备像素比（DPR）为 1.75，线宽为 1 CSS px。两个历史图的实际绘图区宽为 352 / 347 CSS px，高约 52.55 CSS px。

独立 Worker 每 20 ms 产生进度消息。主线程生成并完整写入收到批次的样本。Scope 每跨过 9,600 样本边界替换一帧。消息只携带进度元数据，不复现采集设备或真实波形的传输成本。

| 历史窗 | 修改前 Scope 提交延迟 P95 / ms | 修复版 Scope 提交延迟 P95 / ms |
|---|---:|---:|
| 28 秒 | 317.20 | 25.64 |
| 60 秒满窗 | 416.99 | 18.28 |

长测从空历史窗连续运行 10 分钟。每个检查点测量 6 秒。

| 检查点 | Scope 提交延迟 P95 / ms | 当前积压批数 | 期间积压峰值 |
|---|---:|---:|---:|
| 1 分钟 | 22.08 | 0 | 2 |
| 5 分钟 | 22.24 | 0 | 19 |
| 10 分钟 | 23.27 | 1 | 19 |

检查点没有出现延迟持续增长的趋势。测试期间存在短暂积压，不能称为全程零队列。测试结束取消了尚未接收的 1 批消息，已经接收的批次均完整写入。

“提交延迟”从最近已接收批次的计划时间计到 CPU 绘图调用返回。它不从 Scope 窗内最早样本计时，也不包含 GPU 完成、屏幕扫描和硬件采集延迟。P95 是检查点内第 95 百分位耗时，不是完整 10 分钟的统计。

完整配置、原始构建指纹、精度检查和适用范围见 [高精度轴复测记录](performance-scope-high-precision-20261109.md)。早期 1.5 CSS px 波形诊断见 [持续监视记录](performance-monitoring-20261109.md)，该配置不能代替高精度轴验收。

## 内存与显示抽稀

显示抽稀减少提交的显示样本，原始数据保留容量独立管理。尖峰、NaN 缺口、游标查询和窗口回绕需要分别检查。优化投影无法满足精度检查时，代码退回原绘制路径。

样本容量、JS 堆采样、数值数组和 GPU buffer 不是同一指标。它们不能直接相加作为进程内存峰值。本次长测没有证明无限运行时的队列上界，也没有测量进程内存峰值。

机器可读配置与数值见 [性能矩阵](performance-matrix.json)。现场采集和 Electron 进程间通信链路，需要在采用对应 SDK 后单独复测。
